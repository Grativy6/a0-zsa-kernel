## Focused adversarial repairs

A separate read-only review pass found and then re-probed four identity and
constructor boundaries. The final probes established that:

1. an opening whose CutReceipt payload cut differs from the account origin is
   rejected;
2. a VERSION receipt whose origin differs from the account origin is rejected;
3. arbitrary nested `Decimal` values in an untyped predicted consequence are
   rejected before JSON-mode coercion can collide with strings; and
4. negative-zero JSON is rejected.

Additional tests bind new-account and route-decision identities, prevent
proposal-plane injection of control fields, preserve test/closure separation,
verify exact legacy bytes without claim uplift, require residual split
coverage and distinct children, prevent diagnostics from overriding failed
guards, detect object/account/receipt tampering, and refuse competing serial
token consumption.
